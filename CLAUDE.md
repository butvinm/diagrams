# diagrams

UML/technical diagrams authored as plain **HTML + CSS**, rendered to **PNG** via headless Chromium. Layout is **manual but adaptive**: no auto-layout/auto-routing engine _and_ no hardcoded coordinates — you declare structure with CSS (grid/flex/relative), boxes size to content, and connectors are measured after layout so they follow the boxes. The tool only computes connector geometry; it never routes. Built because PlantUML/Mermaid auto-layout doesn't give positional control — but pixel-coordinate drawing tools are the opposite extreme.

## How it works

1. Author an HTML file with one `<diagram>`; place boxes with CSS grid/flex/absolute; connect them with `<arrow from to>`.
2. `diagrams/kit/kit.mjs` runs in the browser _after_ layout: measures element geometry and draws lifelines + connectors into an SVG overlay. **A connector is a pure function of its two anchor points + path style — it never routes around anything. Do not add obstacle avoidance / pathfinding.**
3. `diagrams/render/render.mjs` (Playwright) loads the file, injects vendored KaTeX + the kit, waits for `data-dg-ready`, and screenshots the `<diagram>` element @2x.

The browser is the layout engine — which is why this is **Node, not Python** (an intentional, required deviation from the global Python preference).

## Map

- `diagrams/` — the shippable plugin (kit, render, skills, command, manifest)
- `diagrams/kit/{primitives.css,kit.mjs}` — components & styles + connector engine (`kit.mjs` also typesets LaTeX via KaTeX before measuring)
- `diagrams/kit/vendor/katex/` — vendored KaTeX (css + js + auto-render + woff2 fonts), shipped so math renders offline
- `diagrams/render/render.mjs` — html → png CLI; also `--html` mode (emits a self-contained embeddable HTML file, no browser; inlines KaTeX only when math is present)
- `diagrams/skills/diagrams/references/COMPONENTS.md` — the components, attributes, and styles (core), with one file per type (`SEQUENCE.md`, `STATE.md`, `CLASS.md`, `DEPLOYMENT.md`, `DFD.md`, `FLOWCHART.md`) plus the cross-cutting `EMBED.md` (embedding / `fluid` / `--html`); **read before authoring or extending diagram types**
- `tests/build-gallery.mjs` + `.github/workflows/pages.yml` — the public GitHub Pages gallery: builds `./site` (gitignored) from `--html` embeds + committed goldens, Node-only (no browser), deployed on push to `master`
- `.claude/skills/dev/SKILL.md` — **dev workflow; read before changing the framework or touching goldens**
- `tests/` — self-contained cases: `cases/<name>/{INTENT.md, ours.html, golden.png, ref.mmd?}` (golden committed; `ours/ref/diff.png` regenerated + gitignored) and `run.mjs`
- `compose.yaml` + `.github/workflows/test.yml` — the pinned-image test environment (local) and CI; goldens are rendered/blessed here, not on bare metal
- `README.md` + `docs/` — human docs: lean landing page, then `docs/GUIDE.md` (authoring) and `docs/DEVELOPMENT.md` (harness/tests). Keep these in sync with the plugin's `COMPONENTS.md` and dev skill, which are authoritative.

## Commands

- Render: `node diagrams/render/render.mjs <in.html> <out.png>` (`DG_SCALE=3` = sharper); `--html` instead of a `.png` output emits a self-contained embeddable file (no browser)
- Gallery: `npm run gallery` (`node tests/build-gallery.mjs` → `./site`, the public showcase; deployed by `pages.yml`)
- Test: `npm run test:docker` (render all → pixel-diff vs golden → build `tests/gallery.html`) — runs in the pinned Playwright image (`compose.yaml`), identical to CI. Bare-metal `npm test` drifts on fonts; do not use it for golden comparison.
- Bless goldens: `npm run test:docker:update` — **only after visual verification** (below); blesses container renders so they match CI.

## Hard rules

- **Snapshot ≠ correctness.** Before creating/updating any golden, verify the render visually — launch a vision subagent that reads the PNG against the case's `INTENT.md`. Never bless an unlooked-at render. Full protocol in `.claude/skills/dev/SKILL.md`.
- Keep connectors pure (anchors → path); no routing.
- **Keep docs in sync.** Whenever a new diagram type lands, rendering/engine behavior changes, authoring syntax changes (elements, attributes, styles, defaults), or anything else user-facing changes, update every affected surface in the same change — don't defer it:
  - `diagrams/skills/diagrams/references/COMPONENTS.md` + the per-type `<TYPE>.md` (authoring reference; a new type gets its own file, linked from `COMPONENTS.md`), plus the cross-cutting `EMBED.md` (embedding / `fluid` / `--html`) when embed behavior changes.
  - `diagrams/skills/diagrams/SKILL.md` (workflow; which type files exist).
  - `docs/GUIDE.md` (how it works, authoring walkthrough) and `docs/DEVELOPMENT.md` (harness/goldens).
  - `README.md` (the **Examples** section — one render per type, add/refresh whenever a diagram type is added or changed — plus quickstart and doc links). Each entry is a Markdown heading with a **source** link to the case's `tests/cases/<type>-basic/ours.html` and an image of the sibling committed `golden.png`, so image and source share a folder with no derived assets to maintain (the golden re-blesses with the suite). The image uses an `<img ... height="360">` tag — the one bit of raw HTML — to cap display height: GitHub renders it cleanly (the height acts as a max, aspect preserved by `max-width:100%`, no distortion), though lightweight Markdown previews like Zed may not honor the tag.
  - this `CLAUDE.md` (Map, Status, Conventions).
- **≥3 test cases per diagram type; reference diagrams come from the Mermaid repo.** Every diagram type must have at least three `tests/cases/` exercising distinct features. Each case's `ref.mmd` is a real example diagram **taken from the Mermaid repository** ([`demos/*.html`](https://github.com/mermaid-js/mermaid/tree/develop/demos) — e.g. `sequence.html`, `state.html`, `classchart.html` — or the docs), copied as-is (record the source), **not hand-authored**; we then build our equivalent `ours.html` and compare in the gallery. This is the point of the suite: validate our rendering against canonical Mermaid examples. Author originals only where Mermaid has no such diagram type — e.g. deployment, whose cases have no `ref.mmd`. Attribution: `THIRD_PARTY.md` (Mermaid is MIT).
- Default branch is `master`.

## Conventions / gotchas

- `<diagram> <lifeline> <point> <arrow>` — plus the sequence extras `<activation> <fragment> <guard> <divider>` — are plain _unknown_ HTML elements swept post-layout — no custom-element registration.
- `arrow` `anchor` is **space-separated**: `anchor="right left"` (src dst). A hyphen would clash with compound names like `top-left`.
- Never put `-->` inside an HTML comment — it closes the comment and leaks text into the diagram.
- **Math (KaTeX):** any label/box may contain LaTeX — `\(…\)` inline, `\[…\]`/`$$…$$` display; a lone `$` is **not** a delimiter (clashes with text). KaTeX is vendored (`diagrams/kit/vendor/katex/`) and injected by `render.mjs`; `kit.mjs:renderMath()` typesets each `<diagram>` before measuring, and is a no-op if KaTeX is absent. KaTeX's own woff2 fonts are font-stable across hosts (the surrounding labels are not), so the Docker golden rule is unchanged. To bump: `npm install katex@<ver>` then re-copy `dist/{katex.min.css,katex.min.js,contrib/auto-render.min.js,fonts/*.woff2}`.
- Goldens are environment-sensitive (Chromium build + fonts), so they are rendered and blessed **only** in the pinned Docker image (`compose.yaml`, `mcr.microsoft.com/playwright:v1.60.0-noble`) — never on bare metal, where the host's fonts differ and every case drifts. CI (`.github/workflows/test.yml`) uses the same image. Keep the image tag in lockstep with the `playwright` version in `package.json`. `DG_NO_SANDBOX=1` (set by the Docker env) lets Chromium launch as root in the container. Diff tolerance is 0.01% in `tests/run.mjs` — renders are bit-for-bit deterministic in the pinned image (every case diffs 0 pixels), so the tolerance is just a hair of slack against a stray pixel, not real drift absorption.
- **Writing the per-type references** (`references/<TYPE>.md`): lead with `## What it is` (what the diagram models + its core rules, and for the four UML types a canonical [uml-diagrams.org](https://www.uml-diagrams.org/) link) and `## Supported` (capabilities grounded in the real `primitives.css` components + `tests/cases`, with an honest **Not built-in / Done by hand** note for the gaps), _then_ the syntax + worked example. `COMPONENTS.md` stays the core (boxes / `<arrow>` / anchors); the type files build on it. References live in the skill and are authoritative — `docs/` links into them (no copy, no symlink).
- **Notation is Mermaid-flavored UML, not strict OMG UML.** Cases model the Mermaid demos (the `ref.mmd`s), so we inherit Mermaid's deviations — rounded participant boxes + a cloned footer row, filled reply arrowheads, rectangular (not pentagon) fragment tabs, flat (not 3-D) deployment nodes. The kit only draws shapes/connectors and enforces **no** UML well-formedness — notation conformance is the author's job. Say "UML-style" / "Mermaid-flavored", not "UML-compliant".

## Status

Implemented: **`sequence`** (lifelines/points/arrows, with participants auto-labelled at both ends via a cloned footer row; self-calls via splines; plus `<activation>` bars trimmed to their messages, `<fragment>`/`<guard>` combined fragments — `alt`/`opt`/`loop`/`ref`/`par`, hugged to their lifelines — and `<divider>` section bands), **state/FSM** (generic `stack` layout + `.state`/`.initial`/`.final` components), **`class`** (multi-compartment `.class` boxes on your own CSS grid; `head="hollow"` for UML generalization), **`deployment`** (`.node` containers holding nested `.artifact` boxes; communication paths via `head="none"`), and **`dfd`** (data flow diagrams: `.external` rectangle / `.process` circle / `.store` open two-line rectangle, data flows via `head="open"`; threat-model flavor adds `.zone` trust regions and `.boundary` trust-boundary lines, all pure CSS + author layout, monochrome), and **`flowchart`** (process flow: seven pure-CSS node shapes — `.terminal` stadium / `.step` rectangle / `.decision` diamond / `.io` parallelogram / `.subroutine` predefined-process / `.database` cylinder / `.preparation` hexagon — connected by ordinary `<arrow>`s, no layout preset, author-placed on a CSS grid; diamond/parallelogram/hexagon drawn via `clip-path` so anchors land on the vertices; loops are manual back-edges, hand-bowed with `spline`+curvature, shown in `tests/cases/flowchart-loop`). Engine supports `straight`/`spline` paths, named + fractional edge anchors, and a `curvature` knob. Label placement is configurable: `label-pos` (`center`/`head`/`tail` or a fraction) slides the label along the connector, `label-anchor` (`center`/`top`/`bottom`/`left`/`right`) pins which side of the label sits on that point — default is `center` (on the line, no offset). Markers: `triangle`/`hollow`/`open`/`diamond`/`filled`. **Math:** any label/box may contain LaTeX, typeset by vendored KaTeX before measuring — `\(…\)` inline, `\[…\]`/`$$…$$` display (no lone `$`); shown in `tests/cases/sequence-math` (a feature case, no `ref.mmd`). Mermaid references render offline (`tests/lib/render-mermaid.mjs`, reusing our Chromium) and appear in the comparison gallery; cases carry an optional `ref.mmd` — except deployment, DFD, the math feature case, and the flowchart-loop feature case, which have no Mermaid equivalent.

Embedding/responsive: a diagram can ship as **live HTML**, not just PNG. `render/render.mjs --html` emits a self-contained file (authored markup + inlined kit CSS/JS, KaTeX inlined as data-URI woff2 only when math is present — ~36 KB without math, ~670 KB with); pure inlining, no browser. The kit gained three embed hooks, all inert in the PNG path (goldens stay 0.000%): `drawOverlay` clears any prior `.dg-overlay` (idempotent redraw), a `ResizeObserver` coalesced to one redraw per `requestAnimationFrame` re-measures anchors + redraws connectors on resize, and `postSize()` posts the diagram size to a host iframe for auto-height (no-op on a top-level page). `primitives.css` adds opt-in `diagram.fluid { width:100% }` (default stays `max-content` for tight PNG crops) so a responsive author layout — `space-between` gutters, `@media` breakpoints — has room to adapt. Responsiveness is **size-adaptive, not topology-adaptive**: connectors follow boxes but never re-route, so spacing/scale changes stay clean while a reflow that changes adjacency crosses fixed anchors (anchors are HTML attrs, can't vary per breakpoint — design each breakpoint around one anchor strategy). Embed = `<iframe>` only (CSS isolation for free); no shadow-DOM/web-component, no inline-with-text. Shown in `tests/cases/class-responsive` (a feature case, no `ref.mmd`; golden captures the 4-col layout at render width). Full reference: `references/EMBED.md`.

Gallery: `tests/build-gallery.mjs` (`npm run gallery`) builds `./site` (gitignored) — a live, user-resizable hero embed of `class-responsive` + one card per type (committed golden + source/live links), Node-only (reuses `--html` + the committed goldens, no browser). `.github/workflows/pages.yml` deploys it to GitHub Pages on push to `master`, independent of the Docker test workflow (enable Pages → "GitHub Actions" once). The dev `tests/gallery.html` (comparison view) is unchanged.

Distribution: `render/render.mjs` self-bootstraps — if `playwright` is missing it `npm install`s into `${CLAUDE_PLUGIN_ROOT}` (plugin has its own `diagrams/package.json`) on first use, and launches Playwright's Chromium or falls back to system Chrome/Edge. Verified from a clean copy with no `node_modules` and no browser download. `node_modules/` is gitignored, so the marketplace clone ships clean.

Testing/CI: the suite renders and blesses goldens **only** inside the pinned Playwright Docker image (`compose.yaml`, `mcr.microsoft.com/playwright:v1.60.0-noble`) — `npm run test:docker` and `npm run test:docker:update` locally, `.github/workflows/test.yml` (push/PR) in CI, all the same image. The goldens were re-blessed in this image and verified bit-for-bit reproducible (0.000% diff). The bare-metal `npm test` path still works but drifts on host fonts and is not authoritative. Renderers honor `DG_NO_SANDBOX=1` to launch Chromium as root in a container. The remote is `git@github.com:butvinm/diagrams`, so CI runs on every push and PR.

Roadmap: the four planned UML types (sequence, state, class, deployment) are all shipped, plus two non-UML types — **`dfd`** (data flow / threat model) and **`flowchart`** (process flow). Embedding (self-contained `--html`, `fluid` responsive diagrams, iframe auto-height) and a published GitHub Pages gallery have landed. No type work queued.
